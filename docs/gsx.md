# gsx — a Go HTML templating language

**Module:** `github.com/gsxhq/gsx`
**Codegen tool:** `github.com/gsxhq/gsx/cmd/gsx`

gsx is a templating language for Go in the same family as
[templ](https://github.com/a-h/templ): you write `.gsx` files that mix HTML
markup with real Go, and a code generator compiles each one into ordinary,
type-checked Go (`.x.go`). There is no runtime template parsing — rendering is
just Go functions writing bytes to an `io.Writer`.

## The idea in one picture

```
  page.gsx  ──(gsx generate)──▶  page.x.go  ──(go build)──▶  binary
  (HTML + Go)                    (generated Go)               (renders HTML)
```

- **You edit** the `.gsx` file.
- **`gsx generate`** turns it into a `.x.go` file (marked
  `// Code generated by gsx; DO NOT EDIT.`).
- **The Go compiler** type-checks the generated code — template mistakes become
  compile errors, and component parameters are ordinary typed Go arguments.

Because the generated files are plain Go, they can be committed to the repo; a
consumer only needs the `gsx` tool when *regenerating*, not when building.

## Components

A component is declared with the `component` keyword. Its parameters are typed
Go values, so callers get compile-time checking:

```go
package ui

import "github.com/gsxhq/gsx"

component Label(children gsx.Node, attrs gsx.Attrs) {
    <label
        data-slot="label"
        class="text-sm font-medium select-none"
        { attrs... }
    >
        { children }
    </label>
}
```

`gsx generate` compiles this into a Go function that returns a `gsx.Node`:

```go
func Label(children gsx.Node, attrs gsx.Attrs) gsx.Node {
    return gsx.Func(func(ctx context.Context, w io.Writer) error {
        // ... writes the <label> markup to w ...
    })
}
```

Components are called from other components with an XML-like tag using the Go
package/identifier name (`<ui.Label>…</ui.Label>`), or as plain function calls.

### Two special parameter types

- **`gsx.Node`** — renderable content. A `children gsx.Node` parameter receives
  whatever markup the caller nested inside the tag; you emit it with
  `{ children }`.
- **`gsx.Attrs`** — a bag of arbitrary HTML attributes passed by the caller.
  Spreading it with `{ attrs... }` merges those attributes onto an element,
  which is how a component stays open to `id`, `aria-*`, `data-*`, event
  handlers, extra `class`es, etc. without enumerating every attribute.

## Expressions and control flow

Anything in `{ … }` is Go. Attribute values can be Go expressions with
`attr={expr}`, and you get the language's real `if`/`for`:

```go
component Options(devices []Device) {
    <select>
        { if len(devices) == 0 {
            <option value="">No devices found</option>
        } else {
            { for _, d := range devices {
                <option value={d.ID}>{d.Name}</option>
            } }
        } }
    </select>
}
```

There are no bespoke loop/branch mini-syntaxes to learn — it is Go `if`, Go
`for`, Go expressions, evaluated where you'd expect.

## Attribute pipelines

gsx supports a pipe operator `|>` for transforming attribute values, e.g.
applying a default:

```go
<button data-variant={variant |> default("default")}>
```

Here `default("default")` substitutes a fallback when `variant` is empty.

## Class lists and Tailwind merging

A `class` attribute can take a comma-separated list of strings, which gsx
concatenates:

```go
<button class={ base, variantClass(variant), sizeClass(size) }>
```

gsx can route the combined class list through a **class merger** so that
conflicting utility classes (as in Tailwind) resolve last-wins instead of
piling up. The merger is configured per project in `gsx.toml`:

```toml
class_merger = "github.com/your/module/ui/merge.Merge"
```

The referenced function receives the assembled classes (base classes plus any
`class` from spread `attrs`) and returns the final string. This is what lets a
caller override a component's default styling by simply passing extra classes.

## Safety: output is escaped by construction

The generated code doesn't blindly concatenate strings — it calls typed
runtime writers that escape by context:

- Text and attribute values go through escaping writers (`AttrValue`, text
  nodes), so interpolated Go values are HTML-escaped.
- URL-bearing attributes (`href`, `src`, `action`, …) are written through a URL
  sanitizer.
- Boolean attributes (`disabled`) render presence/absence rather than a value.
- Spreading `attrs` knows which attributes are URL-typed vs. plain, and skips
  keys already emitted explicitly.

The result is HTML that's safe against injection by default, decided at
generation time rather than by a runtime template engine.

## Rendering

A component returns a `gsx.Node`. Rendering is calling it with a `context.Context`
and an `io.Writer`:

```go
err := Page(data).Render(ctx, w)   // writes HTML to w
```

Because a `Node` is just a function over `(context.Context, io.Writer)`, it
composes naturally with `net/http` handlers, response streaming, and other
`io.Writer` sinks. The `context.Context` threads request-scoped values through
the render tree.

## Tooling

- **`gsx generate`** — compiles every `.gsx` in a package to its `.x.go`. Run it
  as a Go `tool` dependency so the version is pinned in `go.mod`:

  ```go
  // go.mod
  tool github.com/gsxhq/gsx/cmd/gsx
  ```

  ```sh
  go run github.com/gsxhq/gsx/cmd/gsx generate
  ```

- **`gsx.toml`** — per-project configuration (e.g. the `class_merger` above).

- **Generated files** carry `//line` directives back to the original `.gsx`, so
  compiler and debugger positions point at the source you actually wrote.

## Why use it

- **Type safety** — components are typed Go functions; a wrong argument is a
  build error, and refactors are checked by the compiler.
- **No runtime parsing** — templates are compiled to Go; rendering is byte
  writes, not template interpretation.
- **Plain Go interop** — imports, helper functions, control flow, and values are
  just Go. Nothing new to learn beyond the tag syntax and a few builtins
  (`children`, `attrs...`, `|>`).
- **Composable & safe** — `Node`/`Attrs` make components open and nestable, and
  output is context-escaped by default.

## Related / prior art

gsx sits alongside other "HTML-as-typed-Go" approaches — most directly
[templ](https://github.com/a-h/templ), and conceptually JSX/TSX on the frontend
(components, children, attribute spread). Its distinguishing features are the
attribute pipe operator (`|>`), first-class class-list merging via a pluggable
`class_merger`, and the `gsx.Attrs` spread model for open components.
